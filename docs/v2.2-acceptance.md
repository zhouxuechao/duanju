# V2.2 验收：故事时间、时间线锚点与低成本生成档位

## 范围

本轮把故事事实、角色知识、人物/地点/道具/声音/关系状态统一为按 `storyTime` 回放的历史数据；同时完成旧 Timeline 的安全重连，并把开发期媒体模型收敛到显式 `GenerationProfile`。本轮没有执行真实付费 API。

基线提交：`ade1b6279633d7b00737eb152d91c3b2474bc331`。数据库当前最终版本为 V25。

## 时间一致性

- `StoryFactMutation` 始终按 `effectiveFromStoryTime → createdAt → id` 应用，插入顺序不再影响历史回放。
- `CharacterKnowledge` 使用 `[validFromStoryTime, validToStoryTime)` 版本区间。V24 删除旧的“角色+事实只能一条”约束，并保留 `knownFromStoryTime` 兼容读字段。
- `CharacterState`、`LocationState`、`PropState`、`VoiceState`、`Relationship` 和 `CharacterKnowledge` 在创建时拒绝同一实体的重叠区间。
- TTS 排队后使用 Job 内冻结的 VoiceProfile/VoiceState；仅对白 `spokenText` 会在付费提交前与当前值复核。
- 计划连续性缺少身份、定妆、位置、动作或道具持有人时失败；观测画面证据不足记录 `INSUFFICIENT_EVIDENCE`，不会伪装成通过。

## Timeline 历史兼容

- V25 为旧非视频片段按“同一 Timeline + 同一 Shot”匹配具体 VIDEO 片段。
- 唯一匹配会同时写入关系列和 JSON 的 `linkedVideoTimelineItemId`。
- 重复 Shot 造成多匹配时标记 `AMBIGUOUS_REPEATED_SHOT`；没有匹配时标记 `VIDEO_CLIP_NOT_FOUND`。
- `TimelineQualityService` 对上述记录返回 `TIMELINE_RELINK_REQUIRED`。
- 新数据禁止自引用、VIDEO 片段绑定 VIDEO、跨项目或跨 Timeline 绑定；J-Cut/L-Cut 必须绑定具体画面片段。

## GenerationProfile

| 档位 | 图片 | 视频 | 视频分辨率 | 用途 |
| --- | --- | --- | --- | --- |
| TEST（默认） | `doubao-seedream-5-0-260128`，2K | `doubao-seedance-2-0-fast-260128` | 480p | 开发、回归、批量逻辑验证 |
| STANDARD | 同 TEST | 同 TEST | 720p | 小规模人工审查与 Canary |
| FINAL | 显式配置 | 显式配置 | 显式配置 | 预留正式成片能力，不绑定当前高级模型 |

项目、GenerationJob、PromptVersion、Keyframe/AssetView、VideoTake、QCResult 与 CostRecord 保存档位或可追溯快照。质量和成本统计按档位分组。业务领域对象不依赖具体模型 ID；档位通过 `GenerationProfilePolicy` 解析为模型，再由 `ProviderCapabilityRegistry` 解析能力。

Fast 视频能力当前保持 `STATIC_UNVERIFIED`。允许 480p/720p；时长使用配置化 RANGE（默认 4～15 秒、步长 1 秒），11 秒请求不会被旧的 4/8/12 枚举改写。真正 Live Canary 需单独显式执行并保存请求 ID 后，才可把能力状态改为 `LIVE_VERIFIED`。

## 请求快照

视频请求与 VideoTake 保存：`generationProfile`、`modelId`、`resolution`、`ratio`、`desiredDuration`、`providerDuration`、`durationAdaptationReason`、`nativeAudio`、`audioGenerationPolicy`、`watermark`、`capabilityFingerprint`。图片请求使用 `size=2K`，不混入视频 `resolution`。Seedream 返回的 `providerUrl` 仍逐字符原样交给 Seedance。

## 外部阻断

PostgreSQL Testcontainers 在没有 Docker 的机器上保持自动跳过；不伪造通过。Fast/Seedream 新默认模型的真实媒体质量与精确定价仍需显式小规模 Canary，本轮按要求未调用付费接口。

## 验收结果

- H2：V1 → V25、V21 → V22、V24 → V25 迁移及应用集成测试通过。
- PostgreSQL：V1 → current 与 V16 → current 测试保留；本机没有 Docker，两项诚实标记 SKIPPED。
- Backend：539 tests，536 executed PASS，3 SKIPPED（两项 PostgreSQL Testcontainers、一项 Live Canary）。
- Frontend：11/11 PASS，生产构建通过。
- Build：`drama-0.1.0-SNAPSHOT.jar` 生成成功。
- Static contract：真实 Ark 密钥扫描通过；核心 Story/Shot/Continuity/Timeline 未引用具体 Seedream/Seedance 模型 ID；旧 Prompt Builder、旧 CrossShotQc 和运行时 Dialogue fallback 均为 0。
- Live Provider：NOT RUN；Fast 能力继续保持 `STATIC_UNVERIFIED`。

剩余风险：Fast 的精确时长边界、引用素材能力、原生音频以及 480p/720p 的实际服务表现尚待显式付费 Canary 验证。在完成 Canary 前，系统不会把静态能力记录升级为 `LIVE_VERIFIED`。
