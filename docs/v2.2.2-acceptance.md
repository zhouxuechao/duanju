# V2.2.2 验收：自动返修成本锁定与图片画幅参数

## 范围

本轮只处理两项问题：自动 Repair 必须继承来源生成档位，以及 Seedream 图片画幅意图必须进入可追溯的 Provider 参数链。没有新增短剧功能、Provider 或数据库迁移，也没有调用真实付费 API。

检查基线：`3ac6bf72f163fb1f57a2eaf6e72f7645691ed653`。数据库版本保持 V26。

## 自动 Repair 档位与成本锁定

- 视频自动 QC 的 `AUTO_REGENERATE` 改为调用来源 VideoTake 的受控返修入口。
- 自动视频返修固定记录 `regenerationMode=REPLAY_ORIGINAL`、`sourceVideoTakeId` 和 `automaticRepair=true`。
- 来源 VideoTake 的 `generationProfile`、`modelId`、`resolution` 和 `providerOptions` 会覆盖当前项目配置；请求体不能把 TEST 自动升级到 STANDARD 或 FINAL。
- 视频返修仍通过原有 JobService 入队，因此 TestBudgetGuard、项目预算、Shot 付费重试上限和 VideoTake 上限继续生效。
- JobService 的任务顶层档位改为使用已经冻结的 inputSnapshot 档位，CostRecord 因此与实际返修档位一致。
- 已归档的来源关键帧不会因视频返修再次创建重复归档任务。

图片返修把两个维度明确分开：

| 操作 | promptMode | profileMode | 行为 |
| --- | --- | --- | --- |
| Replay Original | ORIGINAL | ORIGINAL | 回放原提示词、档位、模型、尺寸、引用和 Provider 参数 |
| 自动 REBUILD_PROMPT | REBUILD_LATEST | ORIGINAL | 重建修复提示词，但保持原档位与成本参数 |
| 人工 Regenerate Latest | REBUILD_LATEST | CURRENT | 显式使用当前项目档位和当前能力档案 |

自动返修无法通过请求体切换档位；只有人工执行 Regenerate Latest 才会使用当前项目的 STANDARD/FINAL 配置。

## Seedream 图片画幅

- 新增 `ImageOutputProfile` 和 `ImageOutputSizeResolver`。
- `ImageModelProfile` 现在保存 `imageQuality + aspectRatioIntent → providerSize` 的模型专属输出组合。
- Seedream 5.0 当前为 1:1、9:16、16:9 建立统一的静态组合：Provider 继续接收已知可用的抽象 `size=2K`。
- 当前没有官方 Live 验证的具体像素映射，因此没有硬编码 1080x1920、1152x2048 等猜测值。
- 每个图片 Job 保存：`imageQuality`、`aspectRatioIntent`、`providerSize`、`providerAspectRatioVerified`、`imageOutputVerificationStatus` 和 `capabilityFingerprint`。
- 当前所有 Seedream 5.0 画幅组合明确记录 `providerAspectRatioVerified=false`、`STATIC_UNVERIFIED`。
- Replay Original 保留原画幅意图、Provider size 和验证状态；Regenerate Latest 重新解析当前 ImageModelProfile。
- Seedream Adapter 只接收图片参数，未发送视频 `resolution` 或未经验证的 `ratio` 字段。Seedance 请求也未引入图片 `size=2K`。

## 模型与数据库状态

- TEST 仍为 Seedream 5.0、Seedance 2.0 Fast、图片 2K、视频 480p。
- STANDARD 仍使用 720p；FINAL 仍需显式配置，未知模型继续 fail closed。
- Fast 继续使用 4～15 秒、步长 1 秒的 RANGE；11 秒行为未改变。
- 数据继续存入现有 JSON Document，没有新增 V27，数据库最终版本保持 V26。

## Provider 状态与剩余风险

Seedream 5.0 和 Seedance 2.0 Fast 继续保持 `STATIC_UNVERIFIED`。当前 `size=2K` 是实际发送的 Provider 抽象尺寸，但尚不能声明输出像素严格符合 1:1、9:16 或 16:9。只有后续低成本 Live Canary 确认合法尺寸及实际输出后，才能更新 ImageModelProfile 的映射并将 `providerAspectRatioVerified` 升级为 true。

PostgreSQL Testcontainers 仍因本机无 Docker 而跳过。本轮未修改 migration，因此该环境限制没有阻塞两项源码修复。
