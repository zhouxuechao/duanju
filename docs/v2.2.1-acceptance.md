# V2.2.1 验收：知识迁移、Timeline 修复与生成来源追踪

## 范围

本轮只处理源码复核确认的五项问题：CharacterKnowledge 受控迁移、V25 Timeline 错误标记修复、QC 生成来源快照、Relationship 方向性、图片模型能力按模型解析，并清理 Fast 的旧时长枚举配置。没有执行真实付费 API。

检查基线：`79a594259ff5dfa2fdd7a9d19703f6554a82552f`。数据库当前最终版本为 V26。

## 修复结果

### CharacterKnowledge

- 新增正式 transition 入口，在同一事务内关闭当前开放区间并创建下一版本。
- 支持 `UNKNOWN → SUSPECTED → MISUNDERSTOOD → KNOWN`，历史区间可按 `storyTime` 完整回放。
- 拒绝早于最新状态的迁移和同一故事时间冲突；`MISUNDERSTOOD` 强制要求 `believedStatement`。
- 新版本保存 `previousKnowledgeId`、`transitionReason`、`sourceSceneId`、`sourceBeatId`。
- 普通更新入口仍保持不可变约束，不能绕过 transition 覆盖历史。

### Timeline 旧数据

- 保持 V25 不变，新增 append-only 的 `V26__fix_legacy_timeline_relink_scope`。
- 清除 BGM、AMBIENCE 以及没有 Shot 的全局 SFX 被 V25 错加的 relink 标记。
- DIALOGUE 与绑定 Shot 的 SFX 继续保留重连语义；找不到画面仍为 `VIDEO_CLIP_NOT_FOUND`，重复 Shot 仍为 `AMBIGUOUS_REPEATED_SHOT`。
- Timeline QA 只会被真正需要人工重连的条目阻断。

### QC 生成来源

- 人工 QC、图片自动 QC、视频自动 QC、shadow QC 和失败 QC 统一写入生成来源。
- QCResult 保存 `generationProfile`、模型、视频分辨率或图片尺寸；无法从旧数据恢复时明确记录 `UNKNOWN`。
- QualityMetrics 不再把缺失档位默认为 TEST，历史缺失值单独计入 UNKNOWN。

### Relationship 方向性

- 关系键使用 `subjectCharacterId + objectCharacterId + relationshipType`，不再排序双方 ID。
- `A → B` 与 `B → A` 可以同时存在；同方向的不同关系类型也可以同时存在。
- 当前所有关系按有方向处理，避免在没有显式元数据时误合并语义不同的关系。

### 图片模型能力与生成档位

- 新增 model-specific `ImageModelProfile`，显式描述模型族、版本、能力指纹、验证状态、尺寸、比例和引用图片能力。
- `doubao-seedream-5-0-260128` 使用独立静态能力档案，默认 2K，状态保持 `STATIC_UNVERIFIED`。
- 未登记的图片模型返回 `UNVERIFIED_PROVIDER_MODEL`，不会继承 Seedream 5.0 的能力。
- FINAL 仍需显式配置且图片、视频模型都必须存在能力档案；不会自动进入高成本档位。
- Replay Original 保留原始档位、模型、尺寸、能力和引用快照；Regenerate Latest 使用当前项目档位并明确记录 latest 模式。
- TEST 继续使用 Seedream 5.0、Seedance 2.0 Fast、480p、2K；STANDARD 继续使用 720p。
- 删除 Fast 的旧 `4,8,12` 配置入口。Fast 继续使用 4～15 秒、步长 1 秒的 RANGE，11 秒保持原值。

## Migration

- V26 只修复 V25 已写入的错误 Timeline relink 标记，不修改历史 migration。
- H2 升级路径通过：V1 → V26、V16 → V26、V25 → V26。
- PostgreSQL V1 → current 与 V16 → current 测试目标已更新到 V26；本机没有 Docker，两项按真实环境状态跳过。

## Provider 状态与剩余风险

Seedream 5.0 与 Seedance 2.0 Fast 仍为 `STATIC_UNVERIFIED`。本轮按要求没有运行 Live Canary，因此真实服务的图片引用边界、视频精确时长、480p/720p 行为和媒体质量尚未升级为 `LIVE_VERIFIED`。PostgreSQL migration 代码和 Testcontainers 用例已更新，但仍需要在有 Docker 的环境执行一次真实 PostgreSQL 升级验证。

V2.2.1 的五项修复已闭环。本轮不继续扩展 V2 功能；下一阶段应单独执行受控的小规模 Live Canary。
